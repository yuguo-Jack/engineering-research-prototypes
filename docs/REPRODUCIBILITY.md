# 如何理解“能复现”

| 等级 | 实际验证 | 仍需要什么 |
|---|---|---|
| 材料检查 | 结构、链接、依赖声明、版本和数据清单可读 | 不证明代码能执行 |
| 构建与数值测试 | 从所附源码编译，通过数值内核或接口测试 | 不证明完整物理算例 |
| 完整工况复现 | 使用指定原初场/数据，运行完整工况并对比目标量 | 资源与数据必须可获得 |
| 性能复现 | 在约定硬件、资源、精度和计时边界下重复测量 | 不能从功能复现推导速度 |

每个项目明确区分历史结果与当前整理版本的验证。已有原始日志可以核对历史指标，
重建后的完整工况仍需按项目说明执行。硬件控制和目标设备部署另外记录实际目标。

## 通用复现顺序

1. 阅读项目 README、数据条件、环境与授权说明。
2. `doctor` 检查基础工具；安装必要依赖，不为只读结果而安装全部可选软件。
3. 从源码构建并运行不依赖受限数据的测试。
4. 按数据清单准备合法取得的输入，检查 SHA256。
5. 使用明确配置在新输出目录运行，保留 stdout、stderr、配置和运行记录。
6. 比较数值指标与允许误差，必要时重绘图表；性能另按测量条件判断。

当前两个 CFD 项目提供 `python reproduce.py check-run --output runs/<本次运行>`，
将新运行的关键数值与归档原型做回归比较。它和只核对已有材料的 `verify-results`
分别使用，不把已保存日志验证当成重新运行；容差与检查范围见项目复现说明。

可从已有结果开始核对，但最终参考场不能充当原始初场。输入获取受限时应明确说明，
不能用另一个数据集生成的输出冒充同一工况。
